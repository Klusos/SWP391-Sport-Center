## Scope and evidence quality

The audit is a useful lead list, not a current verified defect register. Its source links point to a different Windows user/check-out, its banner refers to `SportCenterDB` rather than a verified current database, and its screenshots are external paths not present in this repository. The reported live counts and visual observations therefore are not evidence about the present runtime. I compared each claim to current source, current business rules, the defense handbook, test inventory, and accepted owner decisions. Findings that require a representative live record or a dynamic interaction are marked accordingly.

Classification meanings: `CONFIRMED_BUG` is contradicted by current code or contract; `ALREADY_FIXED` is covered by current implementation/evidence; `INTENTIONAL_BUSINESS_RULE` follows an explicit accepted rule; `FRONTEND_BACKEND_MISMATCH` describes inconsistent presentation/contract; `MISSING_UI_CAPABILITY` is an absent UI flow (not automatically a policy defect); `BUSINESS_DECISION_REQUIRED` needs owner policy; `COSMETIC` is low-risk presentation; `INSUFFICIENT_EVIDENCE` means the old observation cannot be reproduced or source does not establish it.

**P2-17 subfinding disposition:**

1. `ConsultForm` uses `max={CONSULTATION_TODAY}` while backend requires a strictly past date (`@Past` plus explicit `Asia/Ho_Chi_Minh` check). Selecting today's date is permitted by the control and rejected by the API: `FRONTEND_BACKEND_MISMATCH`, recommended P2 correction is a VN-business-date-aware maximum of yesterday and a distinct invalid-DOB error instead of the current broad 400 message. Existing generic account-conflict wording also handles unrelated 400s, so map errors without disclosing whether an account exists.
2. `CourseConsultationModal` editable Member identity inputs contradict the previously accepted read-only Member identity contract, even though backend safely ignores them: `FRONTEND_BACKEND_MISMATCH`, recommended P1 UX/integrity correction is read-only name/email/phone when authenticated profile data loaded, with actionable missing-profile handling. Do not change server authority.
3. Member cannot self-edit DOB and blank DOB is omitted in the account summary; Course Detail tells the Member to “update” DOB. The no-self-edit permission is `INTENTIONAL_BUSINESS_RULE`; the omission/inaccurate instruction is a `MISSING_UI_CAPABILITY`/copy defect. Minimal correction is display an explicit missing-value message and identify the authorized contact/workflow. Do not add Member DOB editing without an owner decision.
