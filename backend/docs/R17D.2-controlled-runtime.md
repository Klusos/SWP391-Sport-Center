# Controlled local runtime preparation

This procedure does not change the committed/default scheduler behavior. Use it only after an independent read-only check has confirmed the intended recovery SQL Server identity and database. Do not use `backend/run.bat`.

From PowerShell, in the release backend directory:

```powershell
Set-Location E:\00Project\SWP391-Sport-Center-release-deadline\backend
$env:SPORTCENTER_SCHEDULING_ENABLED = "false"
$env:SPRING_JPA_HIBERNATE_DDL_AUTO = "validate"
$env:SPRING_DATASOURCE_URL = "jdbc:sqlserver://127.0.0.1:14333;databaseName=SportCenterDB;encrypt=true;trustServerCertificate=true"
# Supply DB_USERNAME, DB_PASSWORD, JWT_SECRET, and other required secrets privately in this process.
.\mvnw.cmd spring-boot:run
```

Check startup logs to confirm the expected recovery endpoint. The scheduler integration tests prove the false setting removes `ScheduledAnnotationBeanPostProcessor` and all registered scheduled tasks while retaining application services. This procedure itself has not been run against SQL Server.
